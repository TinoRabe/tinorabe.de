Entra External ID for Power Pages: Administrator Handbook

Complete Administrator Handbook for Entra External ID with Power Pages: Setup, Configuration, Best Practices and Troubleshooting for everyday admin work.

    1. Introduction and Objectives

    Objective

    This document describes the administrative tasks in managing Microsoft Entra External ID (an external tenant) for integration with Microsoft Power Pages. It clearly distinguishes between one-time setup tasks and ongoing maintenance work.

    External ID is not Azure AD B2C

    Microsoft Entra External ID is Microsoft's current CIAM solution. It runs in a separate external tenant that you manage in the Microsoft Entra admin center. Azure AD B2C is a separate legacy product: it has not been sold to new customers since May 1, 2025 and is supported until at least May 2030. B2C concepts such as B2C_1_ policies, custom policies (Identity Experience Framework) or AADB2C error codes do not apply to External ID.

    Target Audience

    IT administrators and identity professionals with basic knowledge of Azure/Entra ID. Technical understanding of OAuth2/OpenID Connect is beneficial but not mandatory.

    2. Overview: One-Time vs. Regular Tasks

    One-Time Setup Tasks

    These tasks are performed once during initial setup:

    • Create Entra External ID Tenant
    • Configure App Registration
    • Set up User Flows (Sign-up/Sign-in)
    • Configure Company Branding
    • Enforce MFA via Conditional Access
    • Integration with Power Pages
    • Create test users and perform tests

    Regular Maintenance Tasks

    These tasks occur during ongoing operations:

    • Monitor Sign-in Logs
    • Review failed authentications
    • Deactivate inactive users
    • Rotate client secrets (only if you use one)
    • Test User Flow updates
    • Monitor capacity and costs
    • Apply security updates

    Important

    After successful setup, the administrative effort is minimal. Most activities are limited to monitoring and occasional updates. Portal users reset their passwords themselves; profile data is maintained in Power Pages.

    3. One-Time Setup Tasks

    3.1 Create Entra External ID Tenant
    One-time

    Create a dedicated external tenant for portal authentication. External tenants are created in the Microsoft Entra admin center, not in the Azure portal.

    Procedure:
    1. In the Microsoft Entra admin center navigate to: Entra ID > Overview > Manage tenants
    2. Click on "Create", select "External" and continue
    3. Choose the 30-day free trial or "Use Azure Subscription"
    4. Enter tenant name and domain name (e.g. portalauth)
    5. Select the country/region (for GDPR: an EU country)
    6. Select subscription and resource group, then create (takes up to 30 minutes)
    Important Settings:
    • Domain: [name].onmicrosoft.com is created; sign-in runs via [name].ciamlogin.com
    • Role: Creating the tenant requires at least the Tenant Creator role
    • Billing: MAU-based via the linked Azure subscription

    Important:

    The country/region (data location) and the domain name cannot be changed after creation. Choose carefully.

    3.2 Configure App Registration
    One-time

    Register an application in the external tenant for OpenID Connect sign-in with Power Pages.

    Get the Reply URL from Power Pages first:
    1. In Power Pages design studio: Security > Identity providers
    2. At "Microsoft Entra External ID" select "Configure", enter a name, click "Next"
    3. Copy the Reply URL and keep the tab open
    Procedure:
    1. In the external tenant navigate to: App registrations > New registration
    2. Assign name: power-pages-app
    3. Redirect URI: platform "Web", paste the Reply URL copied from Power Pages (with a custom domain: the matching URL on your domain)
    4. Complete registration
    5. Authentication: enable Access tokens and ID tokens, save
    6. API permissions: select Grant admin consent

    Client secret:

    According to the Power Pages documentation, the dedicated "Microsoft Entra External ID" provider only asks for Client ID, Authority, Redirect URL and Metadata address. A client secret is only needed if you connect External ID via the generic OpenID Connect provider with the authorization code flow.

    Security:

    If you do use a client secret: never store it in code or public repositories. Keep it in a vault such as Azure Key Vault and note the expiry date.

    3.3 Set up User Flows
    One-time

    External ID uses one user flow type for sign-up and sign-in. Password reset is part of the sign-in experience, not a separate flow.

    Create Sign-up and Sign-in Flow:
    1. Navigate to: Entra ID > External Identities > User flows > New user flow
    2. Assign name: power-pages-user-flow (no prefix required)
    3. Identity providers, Email Accounts:
      • Email with password (default) or Email one-time passcode
      • Optional: Google, Facebook, Apple or custom OIDC, once configured as identity providers in the tenant
    4. Select user attributes to collect during sign-up, then "Create"
    5. In the user flow: Applications > Add application, select power-pages-app
    Configure User Attributes:

    Define which data is collected during registration:

    Attribute Collect at sign-up Required
    Email Address Yes (always, verified by one-time passcode) Yes
    Given Name Yes Recommended
    Surname Yes Recommended
    Display Name Optional No

    Attributes are only collected at first sign-up. Which values reach Power Pages is controlled by the app registration (token configuration) and the claims mapping in Power Pages.

    Enable Password Reset:
    1. Prerequisite: the user flow uses Email with password
    2. Navigate to: Entra ID > Authentication methods > Email OTP
    3. Enable Email OTP for all users (or selected groups) and save
    4. Users then see the "Forgot password?" link on the sign-in page

    Tip:

    Test each user flow immediately after creation with "Run user flow" in the Microsoft Entra admin center.

    3.4 Configure Company Branding
    One-time

    Customize the Microsoft-hosted sign-in pages to match your corporate design. External tenants start with a neutral branding without Microsoft logos.

    Branding Options:
    1. Navigate to: Entra ID > Custom Branding, tab "Default sign-in" > "Edit"
    2. Basics: favicon, background image, page background color
    3. Layout: template (full or partial screen), header, footer
    4. Header and sign-in form: logo and banner logo
    5. Footer: your own links for privacy and terms of use
    6. Text: custom texts for sign-in and sign-up
    7. Languages: via language customization in the user flow

    Custom CSS is being retired:

    Microsoft is phasing out custom CSS for company branding. Tenants created after January 5, 2026 no longer get it. Plan your branding with the built-in options. Custom HTML pages (as known from B2C) do not exist in External ID.

    Accessibility:

    Ensure sufficient contrast and WCAG compliance for background images and colors.

    3.5 Multi-Factor Authentication (MFA)
    One-time

    In external tenants, MFA is enforced with a Conditional Access policy, not with a setting inside the user flow.

    Enable MFA:
    1. Enable the second-factor methods under Entra ID > Authentication methods:
      • Email OTP: simplest method (as a second factor after email and password)
      • SMS: available as a paid add-on
      • Passkey (FIDO2): phishing-resistant
    2. Create a policy under Conditional Access > New policy:
      • Users: all users, exclude emergency access accounts
      • Target resources: the Power Pages app (or all resources)
      • Grant: require multifactor authentication
    3. Enable the policy and test it with a test user

    Recommendation:

    Enable MFA at least for administrative accounts. For standard portal users, MFA can remain optional, but should be considered.

    3.6 Integration with Power Pages
    One-time

    Power Pages has a dedicated identity provider for External ID. Use it instead of a generic OpenID Connect provider.

    Required information from the app registration:
    Client ID: Application (client) ID (Overview) Authority: Authority URL (Endpoints) Metadata address: OpenID Connect metadata document (Endpoints), format: https://[tenant].ciamlogin.com/[tenant-id]/v2.0/.well-known/openid-configuration

    Copy the values from App registrations > [your app] > Endpoints instead of building them by hand. B2C-style URLs with a policy name (B2C_1_...) or b2clogin.com do not work for External ID.

    Configuration in Power Pages:
    1. Return to the open tab (design studio: Security > Identity providers > Microsoft Entra External ID)
    2. Enter configuration:
      • Client ID, Authority and Metadata address: [see above]
      • Redirect URL: keep the default; with a custom domain, enter the custom URL (must match the redirect URI of the app registration exactly)
    3. Optional additional settings: external logout, claims mapping, nonce lifetime, use token lifetime, contact mapping with email
    4. Select "Confirm"

    Tip:

    Authentication changes can take a few minutes. For immediate effect, restart the site in the Power Pages admin center.

    Tip:

    After successful integration, disable other Identity Providers (Local Login, Microsoft) to exclusively use Entra External ID.

    3.7 Perform Testing
    One-time

    Perform comprehensive tests before putting the system into production.

    Test Scenarios:
    1. Registration: Create new user and verify email verification
    2. Login: Sign in with newly created account
    3. Password Reset: Complete password reset flow
    4. MFA: Test Multi-Factor Authentication (if enabled)
    5. Token Claims: Verify all required claims are included in token
    6. Logout: Test sign-out (Single Sign-Out)
    7. Error Handling: Test incorrect credentials, expired tokens, etc.

    Go-Live Checklist:

    The system should only be released for productive users after successful tests in all scenarios.

    4. Regular Maintenance Tasks

    4.1 Monitor Sign-in Logs
    Daily

    Monitor authentication activities for anomalies and errors.

    Access to Logs:
    1. In the Microsoft Entra admin center: Entra ID > Monitoring & health > Sign-in logs
    2. Set filter:
      • Time range: Last 24 hours
      • Status: Failed
      • Application: PowerPages-Portal
    3. Check for anomalies (e.g. multiple Failed Logins from same IP)
    Important Metrics:
    • Failed Sign-ins: Should be < 5%
    • MAU (Monthly Active Users): For cost tracking
    • Sign-in Duration: Performance indicator
    • MFA Success Rate: If MFA is enabled

    Set up Alert:

    External tenants keep sign-in and audit logs for only 7 days. Export them via Azure Monitor to a Log Analytics workspace and configure alerts for unusually high error rates there.

    4.2 Deactivate Inactive Users
    Monthly

    Identify and deactivate user accounts that haven't been used for an extended period.

    Procedure:
    1. Identify users without sign-in for more than 90 days (from the sign-in logs exported to Log Analytics, or via Microsoft Graph)
    2. In the Microsoft Entra admin center: Entra ID > Users
    3. Export list and coordinate with business department
    4. Deactivate accounts (do not delete!):
      • Select user
      • Properties > Account enabled: No
    5. Update documentation

    Note:

    Deactivated accounts can be reactivated at any time. Permanent deletion should only occur after explicit approval (GDPR requests).

    4.3 Rotate Client Secrets
    Semi-annual

    Only relevant if your configuration uses a client secret (for example a generic OpenID Connect provider with the authorization code flow). The dedicated External ID provider, configured as documented by Microsoft, does not use one.

    Rotation Process:
    1. Create new Client Secret (see 3.2)
    2. Keep both secrets active in parallel
    3. Switch Power Pages configuration to new secret
    4. Test (Sign-in, Sign-up)
    5. Delete old secret after 48 hours
    6. Document the process

    Important:

    Coordinate secret rotation with the Power Pages team. Unplanned secret changes lead to authentication failures.

    4.4 Monitor Capacity and Costs
    Monthly

    Monitor monthly active users (MAU) and associated costs.

    Cost Tracking:
    • Pricing Model: Entra External ID is billed based on MAU
    • Free Tier: First 50,000 MAU/month free
    • Beyond that: billed per MAU; premium add-ons (e.g. SMS for MFA) have no free tier. Current prices: official External ID pricing page
    1. In the Azure portal: Cost Management > Cost analysis on the subscription or resource group linked to the tenant
    2. Usage also appears there while you are below the free tier
    3. Trend analysis: MAU development over the last 3 months
    4. Configure budget alerts (optional)
    4.5 Security Updates and Patches
    Quarterly

    Regularly check for available updates and security patches.

    Update Sources:
    1. Azure Portal: Service Health > Planned maintenance
    2. Subscribe to Microsoft 365 Message Center
    3. Follow "What's new" for Microsoft Entra External ID
    4. Check Security Advisories

    Automatic Updates:

    Most updates are performed automatically by Microsoft. Manual adjustments are only required for breaking changes.

    5. Monitoring and Troubleshooting

    5.1 Dashboard Metrics

    Metric Normal Value Alert Value Action
    Failed Sign-ins < 5% > 10% Check sign-in logs, test user flow
    Sign-in Duration < 3s > 10s Performance analysis, Azure Support
    Token Errors < 1% > 5% Check token configuration, validate claims
    MAU Growth Steady Sudden Spike Check for bot activity, cost alert

    5.2 Common Errors and Solutions

    External ID reports errors as AADSTS codes. Details for any code: https://login.microsoftonline.com/error?code=[number]

    AADSTS50126: Invalid username or password

    Cause: The user entered wrong credentials

    Solution: A certain share is normal. A sudden spike from few IP addresses points to password spraying: check sign-in logs and consider MFA.

    AADSTS50053: Account locked or sign-in blocked

    Cause: Too many failed attempts, or the request came from an IP address with malicious activity

    Solution: Check the failure reason in the sign-in logs. Inform the user; the lockout ends automatically.

    AADSTS50011: Redirect URI mismatch

    Cause: The redirect URI sent by Power Pages does not match the app registration

    Solution: Align both values exactly (scheme, host, path, trailing slash). Typical after switching to a custom domain.

    AADSTS700016: Application not found

    Cause: Wrong Client ID, or the Authority points to a different tenant

    Solution: Compare Client ID and Authority in Power Pages with the app registration in the external tenant.

    AADSTS7000215: Invalid client secret

    Cause: Only with a client secret: it has expired or the secret ID was entered instead of the value

    Solution: Create a new client secret and update it in Power Pages (see 4.3).

    6. Best Practices and Security

    6.1 Security Best Practices

    1. Principle of Least Privilege

    Grant only the minimum necessary permissions for service accounts and administrators. Use dedicated admin accounts, not personal accounts.

    2. Conditional Access Policies

    Use Conditional Access in the external tenant to require MFA or block access. External tenants support a reduced set of options: conditions for device platform and location; grant controls block, require MFA and require password reset. Risk-based conditions (ID Protection) are not available.

    3. Client Secret Management

    If you use a client secret: never save it in code or configuration files. Use Azure Key Vault. Rotate it every 6-12 months and document all changes.

    4. Audit Logging

    External tenants keep sign-in and audit logs for 7 days. Export them via Azure Monitor to Log Analytics, a storage account or a SIEM and retain them for at least 90 days.

    5. Regular Security Reviews

    Conduct quarterly security reviews. Check: Active permissions, MFA adoption rate, failed sign-in patterns, inactive accounts.

    6.2 Performance Optimization

    Align Session and Token Lifetime

    The Power Pages setting "Use token lifetime" aligns the site session with the token lifetime. Decide deliberately whether you want this behavior.

    Minimize Claims

    Reduce token size by minimizing claims. Request only actually needed user attributes.

    Custom URL Domain and WAF

    Run sign-in on your own domain (e.g. login.contoso.com) and optionally put a web application firewall in front (Azure Front Door, Cloudflare or Akamai integration).

    6.3 Compliance and Data Protection

    GDPR Compliance

    Select an EU country/region when creating the external tenant; this cannot be changed later. Implement processes for GDPR requests (access, deletion, correction). Document all data processing activities.

    Data Residency

    The data location of an external tenant is determined by the country/region chosen at creation. Check it against your compliance requirements before you create the tenant.

    User Consent Management

    Implement clear consent flows for data collection. Document all collected data and their purpose. Enable easy opt-out.

    7. Frequently Asked Questions (FAQ)

    How often must client secrets be rotated?
    Only if you use a client secret (see 4.3). Best practice: every 6-12 months; Microsoft recommends a maximum validity of 12 months. Document every change and coordinate with the Power Pages team.
    Can users delete their accounts themselves?
    Not out of the box. Admins delete users in the Microsoft Entra admin center or via Microsoft Graph. Custom policies do not exist in External ID, so self-service deletion needs your own process (e.g. a request form). Also delete or anonymize the matching contact in Dataverse.
    What does Entra External ID cost?
    Billing is based on monthly active users (MAU). The core offer is free for the first 50,000 MAU per month. Premium add-ons such as SMS for MFA have no free tier. Current prices are on the official External ID pricing page.
    How long are sign-in logs retained?
    In an external tenant, sign-in and audit logs are retained for 7 days. For longer retention, export them via Azure Monitor to Log Analytics, a storage account or a SIEM. Recommendation: at least 90 days.
    Can social logins (Google, Facebook) be used?
    Yes. External ID supports Google, Facebook, Apple and custom OpenID Connect providers. Configure the provider in the external tenant, then add it to the user flow. Consider privacy implications with social logins.
    What happens if Entra External ID fails?
    Sign-up and sign-in to the portal stop working; anonymous pages stay available. Microsoft documents its availability commitments in the Microsoft Online Services SLA. In case of outages, check Azure Service Health and prepare a maintenance notice for the portal.
    How many parallel sessions are allowed?
    There is no documented limit for concurrent sessions per user. Session duration is controlled by the Power Pages settings (e.g. "Use token lifetime") and the token lifetimes in Entra. Access tokens have a variable default lifetime of roughly 60 to 90 minutes.

    8. Checklists

    8.1 Initial Setup Checklist

    External tenant created (EU country/region)
    App registration configured (redirect URI, ID tokens, admin consent)
    Sign-up/Sign-in User Flow created and tested
    Password reset (Email OTP) enabled and tested
    Company branding configured (logo, colors)
    Conditional Access policy for MFA enabled (at least for admins)
    Integration with Power Pages tested (sign-up, sign-in, password reset)
    Log export via Azure Monitor set up (7-day retention in the tenant)
    Documentation created (configuration, secrets, processes)
    Go-live tests performed (all scenarios)

    8.2 Monthly Maintenance Checklist

    Sign-in logs checked for anomalies
    Failed sign-ins analyzed (< 5%)
    Inactive users identified (> 90 days)
    MAU and costs reviewed
    Client secret expiry checked, if used (< 30 days -> plan rotation)
    Azure Service Health checked for planned maintenance
    Configuration backup created (App Registrations, User Flows)

    8.3 Quarterly Security Review Checklist

    Admin permissions reviewed (Principle of Least Privilege)
    MFA adoption rate checked (target: > 90%)
    Audit logs checked for suspicious activities
    Sign-in methods and password reset reviewed
    User flow settings reviewed (attributes, identity providers)
    Conditional Access policies reviewed (MFA, exclusions)
    Compliance documentation updated (GDPR, etc.)
    Disaster Recovery Plan tested

    Summary

    After successful initial setup, the administrative effort for Entra External ID is minimal. Most maintenance tasks can be completed in a few hours per month. Automation (alerts, monitoring) further reduces manual effort.
