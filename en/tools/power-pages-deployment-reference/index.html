Field notes

What the docs don't tell you about code sites

Tested on an enterprise SPA project in October 2026. Not documented on Microsoft Learn, so they sit outside the matrix.

Field note

The upload carries your site configuration

pac pages upload-code-site doesn't only upload the build. It also pushes .powerpages-site: new site settings are created, changed ones are updated. Settings you delete locally stay on the server.

Field note

Pull before you push

Without a fresh download first, an upload overwrites changes made in the Power Pages Management app. In our test, a registration setting that had been switched off would have been switched back on. Treat the server as the source of truth for configuration and the repo for the build.

Migration path

Stuck on SDM? Most gaps close with a migration

Microsoft ships a CLI utility for it: pac pages migrate-datamodel. Not every template can be migrated.

  1. Report. Generate the customization report and fix custom columns, relationships, Liquid, FetchXML, plug-ins and workflows that touch adx_ tables.
  2. Development. Migrate with mode configurationData and capture the result in a solution.
  3. Test and production. Import the solution, then migrate only the references with configurationDataReferences.
  4. Switch. Activate the enhanced data model in a maintenance window. --revertToStandardDataModel is the way back.

Source: Standard to enhanced data model migration overview.
