Power Pages security,by architecture.

22 security and compliance controls, checked against Microsoft Learn for the standard data model, the enhanced data model and single-page application sites. Every control gets one of three states, and every state links to its source.

P
How to read it

Three states, no guessing

Most comparisons mix up "not supported" and "nobody wrote it down". In a security review, that difference matters.

Included

A Microsoft Learn page states it for this architecture, or the feature page applies to all sites and the SPA documentation lists it.

Not included

Microsoft Learn explicitly excludes it for this architecture.

Not documented

Microsoft Learn says neither yes nor no. Test it in your tenant before you promise it to a security reviewer.

Environment and tenant controls such as Customer Lockbox or Purview logging don't act on the site, so the site architecture doesn't decide whether you get them. They are listed separately, with their prerequisites.

Method

How this was checked

  • Every verdict comes from a Microsoft Learn page, linked in the matrix. Release plans, blog posts and forum answers don't count.
  • Standard and enhanced data model: Microsoft states functional parity with no gaps in design studio. Differences listed here are about how you configure a control, not whether you have it.
  • SPA sites: based on Create and deploy a single-page application and Microsoft's Power Pages plugin documentation.
  • Preview features are marked. Microsoft doesn't recommend them for production.
